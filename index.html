Local GGUF chat with the custom WebGPU engine

Open the trial, choose your GPU profile and memory capacity in Models & settings, then select a local GGUF model and load it for chat. A working WebGPU adapter, sufficient memory and supported model architecture, tensors, quantization and tokenizer are required. No model is bundled. A hardware profile is a declared memory budget, not a free-VRAM measurement or compatibility result.

The single HTML file embeds the interface, inference code and tokenizer/template library. This makes the application available for online evaluation without Python, an installer or a build step. Model loading takes additional time. The browser trial does not upload model data, contact a local service or fall back to CPU inference.

Nexus.cpp, online services, voice, camera and teacher features are not included in the trial. Download the full local application for its separate capabilities and local service. Use CPython 3.10 or later; the recorded Linux checks used 3.12.14. Nexus AI uses its own inference engines, not a PyTorch backend.

Browser packaging revision: v25-browser-r1. Scripted no-network boot checks do not establish full-model GPU quality or performance. The original Version 25 native package and its published hashes remain unchanged.

Try related Nexus tools in your browser

  • Compression & Recovery Studio: low-bit compression and recovery controls.
  • Random Initialization Foundry: small-model initialization and training controls.
  • Adapter Optimization Studio: supported local adapter-training workflows.
  • Benchmark Token Studio: disposable scratch-model benchmarks.

These single-file HTML editions include their interface and browser code so evaluators can open a trial without a build step or Python installation. WebGPU and supported local inputs are needed for relevant workloads. Native PyTorch features require the separate full application download.
